# 축 덮개 점검 — 캠페인 **전에** 돌린다

우리가 재는 축 밖의 config 를 남이 추천하는가. 33시간을 쓰고 나서
"그 값을 안 쟀네" 를 알면 늦다.

```bash
python3 scripts/check_axis_coverage.py \
    --vendor docs/baselines/vendor_a6000_828baa64.json
```

종료 코드 **4** 면 근거 없는 공간 밖 값이 있다는 뜻이다. 캠페인 전에
결론을 내라.

---

## 왜 이게 필요한가

`baseline_vendor.py` 를 채점 상대로만 쓰다가 알게 된 것이다. 벤더
휴리스틱이 추천한 **582개 중 35개(6.0%)** 가 우리 탐색 공간 밖이었다.
regret 점수에는 "가장 가까운 config" 로 대체돼 들어가므로 **점수만 보면
안 보인다.**

축 덮개는 채점 지표가 아니라 **설계 점검**이다. 외부 휴리스틱을
"우리가 무엇을 안 재고 있는지 알려주는 탐침" 으로 쓴다.

---

## 두 가지를 구분한다

| | 무엇인가 | 어떻게 |
|---|---|---|
| **진짜 구멍** | 우리 백엔드에서 유효한데 축에 없다 | 축에 넣는다 |
| **남의 공간** | 우리 백엔드에서 성립하지 않는다 | 근거와 함께 `KNOWN` 에 기록 |

벤더 휴리스틱은 cuBLASLt 커널을 겨냥한다. 같은 이름의 축이 다른 것을
뜻할 수 있으므로 "밖에 있다" 만으로는 결론이 안 난다.

### ⛔ `can_implement()` 통과를 근거로 삼지 마라

`stages=1` 이 정확히 그 함정이었다. 확인 절차는 **참조값 대조까지** 간다.

```
emit_cpp -> nvcc -> can_implement() -> 실행 -> 참조 GEMM 과 원소 비교
```

## 2026-08-21 A6000 점검 결과

```
추천   582개 / 형상 66개
공간 밖 35개 (6.0%)

        축          값   추천수  형상  판정
   split_k          5      18     7   ★ 진짜 구멍
    stages          1      15     3   남의 공간 (수치 오류)
 warp_tile  (128, 32)       2     2   ★ 진짜 구멍
```

### `stages=1` — **CUTLASS 2.x 에서 수치가 틀린다**

sm_86, `128x128x32 / 64x64x32`, fp16 in / fp32 accum:

| stages | nvcc | `can_implement` | 실행 | 참조와 일치 | SASS |
|---|---|---|---|---|---|
| **1** | OK | **kSuccess** | OK | **65,536 중 62,674 불일치** (최대 상대오차 32) | LDGSTS 8 |
| 2 | OK | kSuccess | OK | 정확히 일치 | LDGSTS 0 (`MmaPipelined`) |
| 3 | OK | kSuccess | OK | 정확히 일치 | LDGSTS 24 |

`stages=1` 은 `stages=2` 와 **다른 커널**이다 (LDGSTS 유무). 즉 조용히
2단으로 떨어진 것이 아니라 실제로 1단 경로를 타고, 그 경로가 틀린다.

**`can_implement()` 가 통과시키므로 열거기로는 못 거른다.** 축에서 빼는
것이 유일한 방어다. `STAGES = [2..8]` 은 맞았고, 이제 그 근거가 있다.

> 되짚어 볼 것: 우리 열거기의 `explain_kernel` 도 `stages=1` 을 `valid`
> 로 판정했다. 다행히 `STAGES` 에 1 이 없어서 한 번도 열거되지 않았다.
> **축 목록이 마지막 방어선이었다** — 유효성 검사가 아니라.

### `split_k=5` — ★ 진짜 구멍

`SPLIT_K = [1, 2, 3, 4, 6, 8, 12, 16]` 에 5 가 없다. 66형상 중 **58형상**
에서 "요청 == 실제 슬라이스" 를 만족하므로 유효하다.

> 5 를 뺀 것은 의도가 아니라 **누락**이다. 3, 6, 12 는 SM 84 = 2²·3·7 의
> 3배수 가설 때문에 명시적으로 넣었는데(`sm80.py` 주석), 5 는 그 가설에도
> 2의 거듭제곱에도 안 들어가서 아무도 안 물었다.

### `warp_tile=(128, 32)` — ★ 진짜 구멍

`WARP_TILES` 에 없다. `tb=(128,128)`, `(256,64)`, `(128,256)` 에서 유효
판정이 난다 (`tb=(128,64)` 은 `warp_count_mn` 으로 거부).

> 주의: `warp_m=128` 은 **최적 0회 + 스필 100%** 로 제외 후보에 올라 있다
> (`(128,64)` 기준). `(128,32)` 는 누산기가 절반이라 스필 양상이 다를 수
> 있다 — 같은 축이라고 묶어서 지우면 안 된다.

```bash
python3 scripts/check_axis_coverage.py --vendor /tmp/vendor.json
```
