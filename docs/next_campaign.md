# 다음 캠페인(4090 / H100) 준비 메모

A6000 캠페인에서 나온 관찰 중 **다음 GPU 설계에 반영할 것**만 모았다.
지금 A6000 그리드를 바꾸지 않는다 — 캠페인 중간에 바꾸면 앞뒤 데이터를
섞을 수 없다.

## 1. 시작 전 필수 절차 (건너뛰지 말 것)

`README` 의 "새 GPU 에서는 드리프트 3 값을 먼저 재라" 와 같은 내용이다.
클럭 고정 검증과 **같은 위치**의 필수 절차다.

| 값 | A6000 실측 | 왜 필요한가 |
|---|---|---|
| 문턱 (모듈 수) | ~1,200 개 | `segments.kernels` 를 절반 이하로 |
| 상수 성분 | 75 us / 모듈 1,000 개 | 세그먼트 크기 역산 |
| 짧은 커널 왜곡 배율 | 100 배 | 감시 프로브에 짧은 형상이 필요한 이유 |

절차 전체: **`docs/new_gpu_checklist.md`** — 게이트 8개로 정리돼 있고,
이 표의 세 값은 그중 G-4 다. 근거는 `docs/measurement_drift.md` 7 절.

## 2. 형상 그리드 조정안

층별 난이도(= 중앙값 시간 / 최적 시간, 무작위 config 가 최적 대비 몇 배
느린가)를 A6000 에서 재 보니 이렇게 나왔다.

| 층 | 형상 | 난이도 중앙 | 난이도 > 2.0 |
|---|---:|---:|---:|
| **b_kvary** | **12** | **1.77** | **4** |
| e_square | 5 | 1.68 | 1 |
| d_alignment | 5 | 1.66 | 0 |
| c_waves | 11 | 1.56 | 0 |
| a_workload | 40 | 1.50 | 2 |

**층 B 는 형상이 층 A 의 3 분의 1 인데 어려운 형상은 2 배**를 공급한다.
정보량 기준으로는 훨씬 효율적이다. 난이도가 `log K` 와 r = −0.677 로
상관되는 것과 일관된다 — K 가 크면 A/B 읽기가 지배하고 대역폭이 포화되어
config 가 바꿀 수 있는 재사용 패턴에 여지가 없다.

조정안 (총 형상 수는 비슷하게 유지하되 정보량을 높인다):

* 층 B 를 12 → 20 개 정도로. **K < 1024 구간을 더 촘촘히** — 가장 어려운
  형상 상위 둘이 `1024x4096x256`, `1024x4096x128` 로 둘 다 여기다.
* 층 A 의 M 을 10 → 7 개로 줄일 여지가 있다 (난이도가 낮고 중복이 많다).

> ⛔ **층 A 를 너무 줄이면 안 된다.** 실무 워크로드 대표성이 층 A 의 존재
> 이유이고, **"쉬운 형상이 많다" 는 것 자체가 보고할 사실**이다. 난이도만
>보고 설계하면 실제 분포를 왜곡한다. 규칙이 "여기서는 아무거나 골라도
> 된다" 를 배우는 것도 결과의 일부다.

## 3. 측정 시간 개선

`min_warmup = 10` 이라 느린 커널은 워밍업만 자기 실행시간의 10 배를 쓴다.
프로토콜 시간이 p50 26 ms, p90 132 ms, p99 491 ms 로 **느린 꼬리가
평균(64.5 ms)을 지배**한다.

→ 워밍업을 반복 횟수가 아니라 **시간 예산**으로 바꾼다
   (`min_warmup` → `min_warmup_ms`). 측정 조건이라 `env_hash` 가 바뀌지만
   새 캠페인이므로 상관없다.

작업당 벽시계의 3 분의 1 은 GPU 와 무관한 고정 비용이다 (동기화, ctypes,
JSON 기록). **더 빠른 GPU 로 옮겨도 전체 시간이 그만큼 줄지 않는다** —
4090 이 1.6 배 빨라도 25 % 단축에 그친다. 일정은 GPU 성능이 아니라
**작업 수**로 잡는다.

## 4. 여러 GPU 를 동시에 쓸 계획이면

빠른 GPU 한 대보다 여러 대 병렬이 낫다. 각 GPU 는 자기 `env_hash` 로
독립적으로 돌고 번들이 조건을 들고 다니므로 합치는 데 문제가 없다.

**다만 같은 서버라면 간섭 실험을 먼저 하라.** PCIe / 호스트 메모리 / CPU 를
공유하고, 측정 루프의 3 분의 1 이 호스트 측 비용이라 특히 그렇다.
실험: GPU 하나만 돌릴 때와 둘을 동시에 돌릴 때 같은 앵커의 측정값이
달라지는가. 달라지면 순차로 돌아야 하고 병렬의 이점이 사라진다.
