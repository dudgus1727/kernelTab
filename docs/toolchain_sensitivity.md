# 툴체인 민감도 — 표에 유통기한이 있는가

같은 GPU(RTX A6000), 같은 형상 66개, 같은 커널 6,285개를 **두 번** 쟀다.
사이에 바뀐 것은 툴체인이다.

| | 캠페인 A | 캠페인 B |
|---|---|---|
| `env_hash` | `c63710df` | `828baa64` |
| CUDA | 12.4.0 (nvcc 12.4.99) | **13.3.1** (nvcc 13.3.73) |
| CUTLASS | `d4b4b494` (4.6.0-dev) | **v4.7.0** (`dcf215af`) |
| 실행 | 호스트 | **컨테이너** |
| 유저 모드 드라이버 | 580.173.02 | **610.43.02** (forward-compat) |
| 측정 | 980,915 조합 / 33.0 h | 980,915 조합 / **15.3 h** |

## 한 줄 요약

> ### **재측정의 가치는 0.49 % 였다.**
>
> 첫 캠페인의 최적 config 를 새 표에서 그대로 써도 `regret@1 = 1.0049`.
> 15.3 시간을 다시 재서 얻은 것이 그만큼이다.
>
> "CUDA 를 올렸으니 튜닝을 다시 해야 한다" 는 통념은 **적어도 sm_86 에서는
> 근거가 약하다.** 규칙도 GBDT 도 벤더도 전이 손실이 0.3 % 이내이고,
> 축 설계 결론은 하나도 뒤집히지 않았다.
>
> ⚠️ 그래도 **절대 시간을 섞지 마라.** 결론이 유지되는 것과 측정값을 합쳐도
> 되는 것은 다른 이야기다.

## ⚠️ 한계를 먼저 밝힌다

**두 변수가 동시에 바뀐다.** CUDA 버전과 컨테이너(+유저 모드 드라이버)를
분리할 수 없다. 프로토콜(워밍업 시간 예산화)과 세그먼트 크기(500 → 420)도
달라졌다.

따라서 아래 결과는 **"CUDA 13.3 의 효과"** 가 아니다. 읽을 수 있는 것은
**"실무에서 환경을 통째로 옮겼을 때 표가 얼마나 견디는가"** 다. 그것이
소비 쪽이 실제로 마주하는 상황이므로 해석은 가능하다.

측정 조건이 다르므로 **절대 시간을 직접 비교할 때는** 두 표가 같은 클럭
(1350 / 7601 MHz)과 같은 실효 피크(116.1 TF/s)를 쓴다는 것을 근거로 한다.

## 1. 절대 성능 — 변하지 않았다

> **정정 (C-2/C-1 후속)** — 아래 수치는 `status == "ok"` 만으로 계산했다가
> **유효한 시간이 있는 측정 전부**로 다시 냈다. `status != ok` 는 결측이
> 아니다 (`consumer_contract.md` §9). 한쪽 캠페인에서만 플래그가 붙은 줄이
> 빠지면서 **상위 20 Jaccard 가 0.538 로 낮게 나왔었다** (정정 0.739).
> 절대 성능과 전이 regret 은 사실상 그대로다. 아래 §정정 이력 참고.

공통 (형상, 커널, 런타임) 조합 **980,915** 개 — 두 캠페인이 같은 격자를
쟀으므로 한쪽 전용이 **0** 이다:

| | |
|---|---|
| 조합별 시간 변화 | 중앙 **+0.00 %**, p25 −0.43 %, p75 +0.53 %, p1 −5.1 %, p99 +6.0 % |
| 형상별 **최적 시간** 변화 | 중앙 **+0.01 %**, 범위 −3.27 % ~ +2.70 % |
| 개선된 형상 | 4 / 66 |

**CUDA 13.3 은 sm_86 에서 성능을 바꾸지 않았다.** 개선도 회귀도 아니다.
빌드 표본 200개에서 레지스터 중앙값이 144 → 144 로 같았던 것과 일관된다.

> 예전에는 공통을 795,407 로 적었다. 빠진 185,508 줄은 한쪽에서
> `high_outlier_frac` 로 분류된 것이다 — **측정이 없는 것이 아니라 status 가
> 다르다.** 그래서 지금은 전부 센다.

## 2. 순위 안정성 — **개별 순위는 흔들리고, 상위 밴드는 남는다**

| | 값 |
|---|---|
| 상위 20 Jaccard | 중앙 **0.739**, 평균 0.630, 최소 0.026 |
| Kendall tau (상위 50 공통) | 중앙 **0.768**, 평균 0.607, 최소 −0.080 |
| 최적 config 가 **그대로** | **23 / 66 (35 %)** |
| 옛 최적이 새 표에서 **노이즈 이내** | **58 / 66 (88 %)** |

두 줄이 상반돼 보인다. 최적 config 의 **정체**는 65 % 형상에서 바뀌는데,
그 옛 최적은 88 % 형상에서 **여전히 새 최적과 구분되지 않는다.**

> 노이즈 판정에 쓰는 타이머 눈금은 **13.3 표에서 추정**하려 했으나
> 실패했다 — 표에 실린 `time_ms` 는 반복 측정의 **중앙값**이라 눈금 격자에
> 있지 않다 (추정치가 0.001 ns 로 나왔다). `core/noise.py` 의
> `coef_from_observed()` 가 이 경우를 걸러 A6000 눈금(1024 ns)으로 돌아가고
> 그 사실을 출력에 남긴다. 걸러내지 않았다면 이 줄이 88 % 가 아니라
> **77 %** 로 나왔을 것이다.

### 그래서 실제 손해는 얼마인가

**12.4 의 최적 config 를 13.3 에서 그대로 쓰면:**

```
regret@1 = 1.0049          (형상 66개 전부)
중앙 +0.00%   최대 +8.24%   손해 1% 초과 6/66 형상
```

**0.49 %.** 표를 통째로 다시 재서 얻는 이득이 그만큼이다.

### 원인 — 분해능이다, 난이도가 아니다

상위 20 Jaccard 와의 상관:

| | r |
|---|---|
| `distinct_time_frac` (계측 분해능) | **+0.561** |
| `log(최적 시간)` | **+0.666** |
| 난이도 (중앙값/최적) | +0.289 |

**짧은 형상일수록, 구분 가능한 값이 적을수록 순위가 흔들린다.** 난이도와는
거의 무관하다. 즉 churn 의 정체는 **거의 동점인 후보들이 노이즈에 따라
자리를 바꾸는 것**이고, 물리적 최적이 이동한 것이 아니다.

옛 최적이 노이즈를 **벗어난** 8 형상도 같은 그림이다:

| 형상 | `distinct` | 난이도 | Jaccard | 손해 |
|---|---:|---:|---:|---:|
| `128x4096x4096` | 0.124 | 1.55 | 0.250 | +3.13 % |
| `256x12288x4096` | 0.213 | 1.74 | 0.538 | +1.18 % |
| `128x4096x16384` | 0.161 | 1.37 | 0.212 | +0.91 % |

전부 `distinct_time_frac` 이 낮은 쪽이다.

## 3. 규칙·모델 강건성 — ★ **아무것도 무너지지 않았다**

12.4 에서 만든 것을 **13.3 표로 채점**했다.

| | 12.4 | 13.3 | 변화 |
|---|---:|---:|---:|
| 손규칙 (12.4 물리, 리터럴 7개) | 1.1921 | **1.1912** | **−0.08 %** |
| 벤더 휴리스틱 (최근접, 전 형상) | 1.0881 | **1.0912** | +0.28 % |
| 벤더 휴리스틱 (엄격) | 1.0810 (덮개 82 %) | 1.0756 (덮개 76 %) | −0.50 % |
| **GBDT (12.4 학습, 전 형상)** | 1.0134 *(in-sample)* | **1.0127** | **−0.07 %** |
| 12.4 최적 config 재사용 | — | 1.0049 | — |

### GBDT 가 더 무너질 것이라는 예상은 **틀렸다**

12.4 데이터에 밀착된 학습 모델이 규칙보다 취약할 것으로 예상했지만,
**전이 손실이 사실상 0** 이다 (1.0134 in-sample → 1.0127 transfer).

이유는 2 절이 설명한다. GBDT 의 피처는 전부 **빌드 시점 정적 값**
(`mainloop_iters`, `grid_tiles`, 타일 크기, 레지스터…)이고, 그것들은 툴체인이
바뀌어도 거의 같다. 바뀐 것은 `y`(측정 시간)인데 **상위 밴드가 유지되므로**
같은 예측이 여전히 좋은 선택이다.

> **해석 주의.** 이 전이 실험은 학습에 전 형상을 쓴다 — 즉 "안 본 형상에
> 일반화하는가" 가 아니라 **"안 본 조건에 전이되는가"** 만 잰다. 형상
> 일반화는 여전히 5-fold 의 1.0187 이 답이다. 두 질문을 섞지 마라.

### 벤더 휴리스틱의 덮개가 82 % → 76 % 로 줄었다

벤더의 선택 자체는 **66 형상 전부 동일**했다 (두 조건에서 뽑아 대조했고
메타데이터만 달랐다). 줄어든 것은 **그 선택이 새 표에서 `ok` 로 측정된
비율**이다 — `high_outlier_frac` 분류가 달라진 결과이지 휴리스틱이
나빠진 것이 아니다.

## 4. 축별 결론 — 전부 유지

`docs/next_campaign.md` 의 "제외 후보" 가 여기 걸려 있다.

**판정은 "최적 횟수" 가 아니라 "정답 집합(최적 ± 2·noise_floor)에 들어간
형상 수" 로 한다.** 노이즈 바닥을 도입한 뒤로 전자는 너무 약한 기준이다 —
한 번도 1 등이 아니면서 10 형상에서 1 등과 구분 불가능할 수 있다.

| 축 | 최적 횟수 (12.4 / 13.3) | **정답 집합** (12.4 / 13.3) | 판정 |
|---|---:|---:|---|
| `warp_m = 128` | 0 / 0 | **0 / 0** | 유지 — 제외 가능 |
| 스필 발생 warp tile | 0 / 0 | **0 / 0** | 유지 — 제외 가능 |
| tile `256x256` | 0 / 0 | **0 / 0** | 유지 — 제외 가능 |
| `warp_k` 분할 | 0 / 0 | 10 / 11 | 유지 — **제외 불가** |
| `split_k_mode = parallel` | 0 / 0 | 2 / 1 | 유지 — **제외 불가** |
| `stages = 8` | 0 / 0 | 10 / 10 | 유지 — **제외 불가** |
| `stages = 2` | 2 / 2 | 9 / 11 | 유지 — 남긴다 |
| `split_k = 3` | 16 / 17 | 21 / 25 | 유지 — **3 의 배수 기각은 여전히 옳다** |
| `split_k = 6` | 5 / 5 | 9 / 8 | 유지 |
| `split_k = 12` | 2 / 2 | 2 / 2 | 유지 |

**두 캠페인에서 판정이 일치한다** — 어느 기준으로 보든 결론이 안 바뀐다.
다만 **기준을 바꾸니 제외 후보 6 개 중 3 개가 뒤집혔다.** 툴체인이 아니라
**판정 기준**이 결론을 바꾼 것이다 (`docs/next_campaign.md` 4 절).

최적 분포 전체도 거의 같다.

```
stages     12.4 {2:2, 3:52, 4:4, 5:4, 6:3, 7:1}
           13.3 {2:2, 3:49, 4:7, 5:3, 6:3, 7:2}
split_k    12.4 {1:21, 2:13, 3:16, 4:8, 6:5, 8:1, 12:2}
           13.3 {1:22, 2:13, 3:17, 4:6, 6:5, 8:1, 12:2}
warp_m     12.4 {16:8, 32:10, 64:48}   13.3 {16:9, 32:11, 64:46}
```

**`split_k_mode` 는 두 캠페인 모두 66/66 이 `serial`** 이다. 두 GPU 에서
0 회면 빼기로 한 기준(`next_campaign.md` 4 절)의 절반이 채워졌다 — 다만
그 기준은 **다른 GPU** 를 뜻했으므로 4090 을 기다린다.

## 5. 결론

> **표에 유통기한이 있는가 — 툴체인 한 세대 정도로는 없다.**

* 절대 시간이 **안 바뀐다** (중앙 0.00 %).
* 개별 순위는 흔들리지만 **그 흔들림은 계측 분해능이 만든 것**이고
  (`r = +0.58`), 상위 밴드는 유지된다.
* 12.4 의 최적 config 를 그대로 써도 **regret 1.0049**.
* 규칙도 GBDT 도 벤더도 **전이 손실이 0.3 % 이내**.
* 축 설계 결론이 **하나도 뒤집히지 않았다**.

### 이것이 무엇을 뜻하나

* **한 번 만든 규칙을 오래 쓸 수 있다.** kernelRule 의 전제가 성립한다.
* **재측정의 가치는 0.49 %다.** 툴체인이 바뀌었다고 33 시간을 다시 쓰는
  것은 정당화되지 않는다 — 다만 `env_hash` 격리는 유지해야 한다.
  절대 시간을 섞으면 안 되는 것과, 결론이 유지되는 것은 다른 이야기다.
* **"해석 가능한 규칙이 학습 모델보다 강건하다" 는 증거는 얻지 못했다.**
  둘 다 똑같이 강건했다. 그 주장을 하려면 **아키텍처가 바뀌는**
  전이(A6000 → 4090)를 봐야 한다.

### 다음에 확인할 것

| | 무엇 | 왜 |
|---|---|---|
| 1 | A6000 → **4090** 전이 | 아키텍처가 바뀐다. 여기서야 규칙과 모델이 갈릴 수 있다 |
| 2 | 컨테이너 안에서 **CUDA 버전만** 바꾸기 | 두 변수를 분리한다 |
| 3 | `distinct_time_frac` 낮은 형상을 채점에서 가중 낮추기 | churn 의 58 % 를 설명하는 축이다 |

플래그가 붙은 줄이 빠지면 겹침이 구조적으로 낮게 나온다.

아니라 77 % 로 나왔을 것이다 — `core/noise.py::coef_from_observed` 의
타당성 가드가 잡았다.
