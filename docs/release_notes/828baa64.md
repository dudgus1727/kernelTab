## 이 표와 첫 캠페인의 관계

같은 GPU 를 **두 번** 쟀다. 둘 다 유효하고 용도가 다르다.

| | `c63710df` (첫 캠페인) | **`828baa64` (이 표)** |
|---|---|---|
| CUDA | 12.4.0 (nvcc 12.4.99) | **13.3.1** (nvcc 13.3.73) |
| CUTLASS | `d4b4b494` (4.6.0-dev) | **v4.7.0** (`dcf215af`) |
| 실행 | 호스트 | **컨테이너** (재현 가능) |
| `schema_version` | 1 (`tick_ms` 없음) | **2** |
| 표 컬럼 | 96 | **98** (`distinct_time_frac` 추가) |
| 측정 시간 | 33.0 h | **15.3 h** |
| 용도 | 파이프라인 검증. 개발용으로 유통 중 | **본 캠페인** |

**첫 캠페인 표를 내리지 않는다.** 소비 쪽이 개발에 쓰고 있고, 두 표의
대조가 아래 연구의 재료다.

### 두 표를 대조했다 — `docs/toolchain_sensitivity.md`

> **재측정의 가치는 0.49 % 였다.**
> 첫 캠페인의 최적 config 를 이 표에서 그대로 써도 `regret@1 = 1.0049`.

| | |
|---|---|
| 형상별 최적 시간 변화 | 중앙 **+0.00 %** (범위 −3.27 ~ +2.70 %) |
| 최적 config 가 그대로 | 15 / 66 (23 %) |
| **옛 최적이 새 표에서 노이즈 이내** | **50 / 66 (76 %)** |
| 12.4 손규칙을 이 표로 채점 | 1.1921 → **1.1912** |
| 12.4 학습 GBDT 를 이 표로 채점 | 1.0134 → **1.0127** |
| 축 설계 결론 | **하나도 안 뒤집혔다** |

순위가 절반쯤 바뀌어 보이지만 **성능이 바뀐 것이 아니다.** churn 은
계측 분해능이 만든다 (`distinct_time_frac` 과 상관 r = +0.58, 난이도와는
+0.18). 자세한 것은 저장소의 `docs/toolchain_sensitivity.md`.

> ⚠️ **그래도 두 표의 절대 시간을 섞지 마라.** 결론이 유지되는 것과
> 측정값을 합쳐도 되는 것은 다른 이야기다. `env_hash` 로 격리하라.
